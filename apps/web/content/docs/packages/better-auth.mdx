A [better-auth](https://www.better-auth.com/) plugin that handles the complete SIWS flow -- nonce generation, message building, signature verification, user management, and session creation.

## Server Plugin

```ts title="auth.ts"
import { betterAuth } from 'better-auth'
import { siws } from '@siws/better-auth'

export const auth = betterAuth({
  baseURL: 'https://example.com', // or set BETTER_AUTH_URL
  // ... your database and other config
  plugins: [
    siws({
      statement: 'Sign in to MyApp',
      expirationTime: 600, // 10 minutes
      cluster: 'mainnet-beta',
    }),
  ],
})
```

Requires better-auth `>=1.7.7 <2`.

The message `domain` and `uri` come from the `domain` / `uri` options, or from the base URL configured for better-auth: the static `baseURL` option or the `BETTER_AUTH_URL` environment variable (`example.com` and `https://example.com` above). They are never read from the `Origin` or `Host` request headers. If none of these is set, both endpoints fail with `DOMAIN_NOT_CONFIGURED`, even though better-auth itself would fall back to the request's Host. A dynamic `baseURL` (`{ allowedHosts }`) counts as not configured; set `domain` and `uri` instead.

### Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `domain` | `string?` | `baseURL` host | RFC 3986 authority bound into the message, e.g. `example.com` or `localhost:3000` |
| `uri` | `string?` | `baseURL` origin | URI written into the message |
| `statement` | `string?` | -- | Statement shown when signing |
| `expirationTime` | `number?` | `300` | Expiration in seconds |
| `cluster` | `Cluster?` | `'mainnet-beta'` | Default Solana cluster |
| `resources` | `string[]?` | -- | Resource URIs to include |
| `emailDomainName` | `string?` | `'siws.local'` | Domain for synthetic emails |
| `anonymous` | `boolean?` | `true` | Allow sign-up without email |
| `schema` | `object?` | -- | Custom `solanaAddress` table schema |

## Client Plugin

```ts title="auth-client.ts"
import { createAuthClient } from 'better-auth/client'
import { siwsClient } from '@siws/better-auth/client'

export const auth = createAuthClient({
  plugins: [siwsClient()],
})
```

### Client Methods

#### `auth.siws.getNonce(input)`

Request a nonce and pre-built message for signing. Like all better-auth client calls, it returns `{ data, error }`.

```ts
const { data, error } = await auth.siws.getNonce({
  address: '7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZRuJosgAsU',
  cluster: 'mainnet-beta', // optional, uses server default
})
```

**Input:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `address` | `string` | Yes | Solana wallet address |
| `cluster` | `Cluster?` | No | Solana cluster override |

**Response:**

| Field | Type | Description |
|-------|------|-------------|
| `nonce` | `string` | Server-generated nonce |
| `message` | `string` | Complete SIWS message ready for signing |

#### `auth.siws.verify(input)`

Verify a signature and create a session. `address` and `cluster` must match the ones used to request the nonce.

```ts
const { data, error } = await auth.siws.verify({
  message,
  signature: bs58.encode(signatureBytes),
  address: walletAddress,
  cluster: 'mainnet-beta',
  email: 'user@example.com', // optional
})

if (data) {
  // User is authenticated, session cookie is set
  console.log(data.user)
} else {
  console.error(error.code) // e.g. 'INVALID_OR_EXPIRED_NONCE'
}
```

**Input:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `message` | `string` | Yes | The signed SIWS message |
| `signature` | `string` | Yes | Base58-encoded signature |
| `address` | `string` | Yes | Solana wallet address |
| `cluster` | `Cluster?` | No | Cluster override |
| `email` | `string?` | No* | User email (*required if `anonymous: false`) |

**Response:**

| Field | Type | Description |
|-------|------|-------------|
| `success` | `true` | Always `true`; failures are returned as `error` |
| `token` | `string` | Session token |
| `user` | `object` | `{ id, address, cluster }` |

## Verification

`/siws/verify` checks, in order:

1. The message parses as a SIWS message.
2. The message `address` and `cluster` equal the request `address` and `cluster`.
3. A nonce was issued for that address, cluster and nonce and has not expired. It is consumed atomically, so each nonce is single use even under concurrent requests, and a failed attempt also uses it up. The client must request a new nonce.
4. The message `domain` equals the configured domain.
5. The Ed25519 signature is valid for the message address.

## Error Codes

Errors are returned with a `code` from `SiwsPluginErrorCode`:

| Code | Status | When |
|------|--------|------|
| `INVALID_ADDRESS` | 400 | `address` is not a valid Solana address |
| `INVALID_CLUSTER` | 400 | `cluster` is not `mainnet-beta`, `devnet` or `testnet` |
| `INVALID_MESSAGE` | 400 | The message is not a valid SIWS message |
| `EMAIL_REQUIRED` | 400 | `anonymous: false` and no `email` was sent |
| `ADDRESS_MISMATCH` | 401 | Message address differs from the request `address` |
| `CLUSTER_MISMATCH` | 401 | Message cluster differs from the request `cluster` |
| `INVALID_OR_EXPIRED_NONCE` | 401 | Nonce never issued, already used, or expired |
| `DOMAIN_MISMATCH` | 401 | Message domain differs from the configured domain |
| `VERIFICATION_FAILED` | 401 | Invalid signature or failed message verification |
| `EMAIL_ALREADY_IN_USE` | 422 | `anonymous: false` and a user with that email exists |
| `DOMAIN_NOT_CONFIGURED` | 500 | No `domain`/`uri` option and no static `baseURL` / `BETTER_AUTH_URL` |

Unexpected server errors return a generic `500`. The details go to the better-auth logger, not to the client.

The codes and messages are also exported as `SIWS_ERROR_CODES` and registered as the plugin's `$ERROR_CODES`.

## Endpoints

The plugin registers two API endpoints:

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/auth/siws/nonce` | Generate nonce and message |
| `POST` | `/api/auth/siws/verify` | Verify and create session |

## Database Schema

The plugin creates a `solanaAddress` table to store linked wallet addresses:

| Column | Type | Description |
|--------|------|-------------|
| `id` | `string` | Primary key |
| `userId` | `string` | Foreign key to `user.id` (cascade delete) |
| `address` | `string` | Solana wallet address (indexed) |
| `cluster` | `string` | Solana cluster |
| `isPrimary` | `boolean` | Whether this is the primary address |
| `createdAt` | `date` | When the address was linked |

Run your better-auth database migrations to create this table.

The pair (`address`, `cluster`) has a unique index. Sign-in creates the user, the address link and the account in one transaction. If two first sign-ins for the same wallet (or the same email when `anonymous: false`) run at the same time, the database's unique constraints reject the second one, which rolls back, retries once and signs into the user the first one created. Use an adapter with transaction support (Postgres, MySQL, SQLite) to get this guarantee; the memory adapter enforces neither constraint.

> **Upgrading from 0.1.x:** 0.2.0 adds the unique index, so run your better-auth migrations (`npx @better-auth/cli migrate` or `generate`). If existing data has duplicate (`address`, `cluster`) rows, remove them first or the migration will fail.

```ts title="auth.ts"
import { betterAuth } from 'better-auth'
import { siws } from '@siws/better-auth'

export const auth = betterAuth({
  baseURL: 'https://example.com',
  database: {
    // your database config
  },
  plugins: [
    siws({
      statement: 'Sign in to MyApp',
      expirationTime: 300,
      cluster: 'mainnet-beta',
    }),
  ],
})
```

```ts title="auth-client.ts"
import { createAuthClient } from 'better-auth/client'

```

```tsx title="connect-wallet.tsx"
import { auth } from './auth-client'
import bs58 from 'bs58'

async function signInWithSolana(wallet: { publicKey: PublicKey; signMessage: (msg: Uint8Array) => Promise<Uint8Array> }) {
  const address = wallet.publicKey.toBase58()

  // 1. Get nonce and message from server
  const { data: nonceData, error: nonceError } = await auth.siws.getNonce({
    address,
    cluster: 'mainnet-beta',
  })
  if (nonceError) throw new Error(nonceError.message)

  // 2. Sign with wallet
  const signatureBytes = await wallet.signMessage(
    new TextEncoder().encode(nonceData.message)
  )

  // 3. Verify and create session
  const { data, error } = await auth.siws.verify({
    message: nonceData.message,
    signature: bs58.encode(signatureBytes),
    address,
    cluster: 'mainnet-beta',
  })

  if (error) throw new Error(error.message)
  console.log('Signed in as:', data.user)
}
```
